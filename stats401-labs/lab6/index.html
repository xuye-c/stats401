Lab 6: Hierarchical GDP Treemaps

1. Dataset Description

This assignment visualizes a synthetic world GDP hierarchy: continent, then area (subregion), then country. Each country has a GDP in billions of U.S. dollars and a status of Increase, Unchanged, or Decrease. The same nested JSON is drawn twice, with two D3 tiling algorithms, so area still encodes GDP and color still encodes status.

2. Squarify treemap

d3.treemapSquarify keeps rectangles closer to squares. Click a country to zoom one level at a time (continent, then area, then country). Click the path above the chart, or the dark padding around the current view, to zoom back out.

3. SliceDice treemap

d3.treemapSliceDice alternates horizontal and vertical splits by depth. Continents form large strips, then areas cut those strips, then countries fill the remaining space. Zoom works the same way as in the squarify view.

4. Design Description

Rectangle area encodes GDP because treemaps are built for part-to-whole comparison: the United States and China occupy large cells, while Kenya is a thin remainder. GDP status is categorical with three ordered classes, so I mapped it to a small diverging palette—teal for Increase, muted gray-blue for Unchanged, and coral for Decrease. Color is independent of size, so a small growing economy stays visible without competing with GDP magnitude. Continent, area, and country are shown by nested padding, parent labels, and leaf labels rather than a third color, which would collide with status. Tooltips repeat the full path and both attributes when a cell is too small to label.

Squarify makes GDP comparisons easier because similar values look like similar squares, but sibling areas can sit in irregular clusters, so continent–area nesting is harder to scan. SliceDice is weaker for comparing similar GDPs because many cells become long bars, but the hierarchy is easier to read: each depth uses a consistent cut direction, so continents read as slabs and areas as bands inside them.

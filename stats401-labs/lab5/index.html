Lab 5: Interactive Network Visualization

1. Dataset Description

This assignment visualizes a synthetic urban transit network with 50 stations and 50 direct connections. Stations belong to five districts (Central, North, South, East, West) and are classified as Local, Transfer, or Terminal. Each station also has an approximate daily passenger volume. Direct routes are Metro, Express, or Shuttle services, each with a travel time in minutes. Each route is a directed station-to-station connection: source is the first station and target is the second. Arrowheads in the node-link view follow that source → target order.

2. Node-Link Visualization

The dashed X splits the canvas into North, East, South, and West. The square in the middle is Central. A station stays in its district; its exact place inside that region is arranged by the force layout, not by real map coordinates. Link width encodes travel time. Arrowheads encode the directed route from source to target.

3. Node-Link Design Description

Node channels

  • Daily passengers — color

I did not use size for daily passengers because size is easy to read as the physical footprint of a station, which I think would be misleading. Color is not the strongest channel for a quantitative variable, but it still gives a quick sense of which stations are busier than others.

  • Station type — shape

Station type is categorical, so I mapped it to shape. Distinct shapes make it easier to spot Local, Transfer, and Terminal stations, and to see how those roles sit in the network.

  • District — position

I used position for district because district is already a geographic idea. An X through the middle of the canvas splits North, East, South, and West, and a square at the crossing marks Central. That gives the four outer districts a shared open plane, so links are not trapped inside five small boxes. The mapping is still not a real map: the data do not include coordinates, so a point’s place inside its wedge or square is only a layout position. The note under the chart makes this limit explicit.

Link channels

  • Route type — color

Route type is also categorical, so I encoded it with color. Different hues help readers see whether a connection is Metro, Express, or Shuttle. To keep those colors separable from the passenger gradient on the nodes, the route colors use lower saturation and higher lightness. Nodes also have a light outline so their shapes do not blend into the arrowheads.

  • Travel time — width

Travel time is quantitative, so I mapped it to link width. I first tried length, but district regions and travel-time springs fought each other geometrically. Width stays readable no matter where the stations sit: thicker links are longer trips, and thinner links are shorter ones.

Interaction design

  • Hovering over a node — highlight the node and its connected links

Hovering a station highlights that station and the routes that touch it. This makes it easier to see how a station is connected and what role it plays in the network.

  • Hovering over a link — highlight the link and its endpoints

Hovering a route highlights that link and the two stations it connects.

  • Dragging a node — keep the station in its district

Stations can be dragged to reduce overlap. A dragged station stays where it is released, but it cannot cross the X or leave the Central square.

  • Filtering by route type

When a route type is selected, only those links keep their color. The rest are grayed out so it is easier to see where Metro, Express, or Shuttle service sits in the network.

4. Adjacency Matrix

Rows and columns are stations, ordered by station type (Local, then Transfer, then Terminal). Thick lines separate those groups. A filled cell is a direct route; cell color is route type. Label color is the station’s district. The matrix is shown symmetrically, so a directed route A → B appears in both (A, B) and (B, A).

5. Matrix Design Description

Grid

  • Row / column — station

Each row and each column is one station, so a cell is the pair of those two stations. Axis labels use station ids so 50 names do not overlap; the full name is in the tooltip.

  • Filled cell — direct connection

A filled cell means the two stations have a direct route. Empty cells are the dark background. The matrix is drawn symmetrically: a directed route A → B appears in both (A, B) and (B, A), so “who is linked to whom” is easy to scan. The actual direction is kept in the tooltip.

Cell channels

  • Route type — color

Cell color uses the same muted Metro / Express / Shuttle palette as the node-link links, so route type matches across the two views. Color is a reasonable channel here because route type is categorical and there are only three classes.

  • Travel time — tooltip, not opacity

I did not map travel time to cell opacity. Fading the cells would mix with route-type color and make Metro / Express / Shuttle harder to tell apart. Travel time is shown in the tooltip instead, together with direction (source → target).

Label and order

  • District — label color

The matrix cannot use map position the way the node-link view does, so district is encoded in the color of the row and column labels. That keeps geographic membership visible while the grid itself stays a connection table.

  • Station type — ordering and divider lines

Stations are ordered Local, then Transfer, then Terminal, with thick lines between those blocks. A filled cell inside a block is a same-type connection; a cell that crosses a divider is a route between different station types. I did not order by district, so district-to-district structure does not appear as large blocks—only as label color.

Interaction

  • Hovering over a cell — highlight the pair and show a full tooltip

Hovering a cell highlights its row and column and opens a tooltip with both stations’ id, name, district, station type, and daily passengers. If a route exists, it also shows direction, route type, and travel time; if not, it states that there is no direct route.

6. Network Questions and Findings

1. Which stations appear central in the network?

How well: well, mainly from the node-link view.
View: node-link; matrix as a check.
Encoding / interaction: hover highlighting shows how many neighbors a station has; in the matrix, a station with more filled cells in its row/column has more direct routes.

The network is mostly a long chain, so few stations look like global hubs. The stations that appear most central are the ones with three connections—two neighbors on the chain plus an extra hop—such as Stations 4, 7, 10, 13, 16, 18, 21, 23, 25, 29, 31, 33, 34, and 38. Hovering them lights up more links than hovering a typical Local stop on the chain. A few high-id stations sit almost alone in their district region; they are leaves, not centers.

2. Which districts are strongly connected to one another?

How well: partially.
View: node-link is more useful; the matrix only partially, because I ordered by station type rather than district.
Encoding / interaction: district regions (the X and the Central square) and the links that cross them; hover to see which extra hops leave a district. Matrix label color shows membership but not a district-block pattern.

Adjacent districts on the cycle Central → North → South → East → West → Central are the most strongly tied, because the main chain steps through that order. Extra hops also stitch non-adjacent pairs (for example North–Central on Station 7 to Station 31, or East–West on Station 29 to Station 50). Central is the only district with visible within-district routes in the extra links (Stations 1–16 and 21–41). The matrix does not make this district pairing obvious.

3. Where are transfer or terminal stations located in the topology?

How well: well.
View: both.
Encoding / interaction: node-link uses shape (square = Transfer, triangle = Terminal); the matrix puts each type in its own block, separated by the thick lines.

Transfer and Terminal stations are spread along the chain, not clustered at one geographic end. Terminals are not only “ends of the line”: Station 1 (Central, triangle) starts the chain, but many other triangles sit in the middle of the path. In the matrix, most filled cells sit off the type blocks, which matches a chain that mixes Local, Transfer, and Terminal rather than connecting only like with like.

4. Which stations have high passenger volume?

How well: well in the node-link view; not easily as a pattern in the matrix.
View: node-link.
Encoding / interaction: sequential color (blue → yellow → red) and the passenger legend; tooltips give the count. The matrix does not encode passengers except in the tooltip.

The reddest nodes are the busiest. Stations 46–50 are among the highest-volume stations (Station 50 is the most red). Several of those high-volume stations are not the most connected ones: they sit toward the edge of the West, East, or North regions with few neighbors. Busyness and topological centrality therefore do not line up in this network.

5. Where are the longest direct travel-time connections?

How well: well in the node-link view, though width is weaker than position would have been; only by tooltip in the matrix.
View: node-link; matrix as a check.
Encoding / interaction: link width and route tooltips. Hovering a thick line confirms the minutes. Matrix cells do not encode time except in the tooltip.

The thickest links are the longest hops. They are Express routes: Station 7 → Station 31 (16 min), Station 18 → Station 34 (15 min), and Station 29 → Station 50 (14 min). These extra hops stand out against the thinner chain steps.

6. Are particular route types concentrated in particular parts of the network?

How well: well.
View: both.
Encoding / interaction: link/cell color, the route-type filter in the node-link view, and scanning color inside the matrix blocks.

Route types are mixed, not confined to one district or one station type. Filtering to Metro, Express, or Shuttle still lights links in several district regions, and the matrix shows all three colors both inside and across the Local / Transfer / Terminal blocks. Express does stand out among the longest extra hops (the 14–16 minute links above), but as a class it is not limited to one region of the map.
